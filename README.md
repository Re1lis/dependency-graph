# Dependency Graph

Консольное приложение для анализа зависимостей пакетов Alpine Linux.
Проект реализует первые четыре этапа практической работы для варианта №28.

Программа получает описание пакетов из репозитория Alpine Linux, находит
выбранный пакет и строит граф его прямых и транзитивных зависимостей.
Получение зависимостей выполняется самостоятельно по данным `APKINDEX`.
Менеджер пакетов для этой операции не используется.

## Реализованные этапы

### Этап 1. Конфигурация

На первом этапе программа принимала настройки из командной строки, проверяла
их и выводила в формате `ключ=значение`. Посмотреть этот этап можно на теге
`stage-1`.

### Этап 2. Сбор данных

Программа загружает `APKINDEX.tar.gz` из репозитория Alpine Linux, находит
пакет по имени и версии и выводит его прямые зависимости.

### Этап 3. Основные операции

Программа строит полный граф рекурсивным BFS-обходом. Поддерживаются ограничение
глубины, фильтрация по подстроке, циклические зависимости и тестовый режим с
локальным файлом. Записи Alpine вида `libcurl=...` и `so:libz.so.1`
самостоятельно сопоставляются с именами пакетов через поле `p` индекса.

### Этап 4. Порядок загрузки

Программа выводит зависимости перед пакетами, которым они нужны.
Общие зависимости выводятся один раз. Если граф содержит цикл, программа
сообщает, что определить порядок загрузки невозможно.
С флагом `--load-order` выводится только порядок загрузки.

D2 и сохранение SVG относятся к пятому этапу.

## Параметры командной строки

| Параметр | Назначение |
| --- | --- |
| `--package` | имя анализируемого пакета |
| `--repository` | URL репозитория или путь к тестовому файлу |
| `--test-mode` | читать локальный тестовый граф вместо URL |
| `--version` | версия выбранного пакета |
| `--output` | имя будущего SVG-файла |
| `--ascii-tree` | флаг будущего вывода ASCII-дерева |
| `--max-depth` | максимальная глубина обхода графа |
| `--filter` | подстрока для исключения пакетов |
| `--load-order` | вывести порядок загрузки для четвёртого этапа |

На четвёртом этапе `--output` и `--ascii-tree` принимаются и проверяются, но
полноценная визуализация и ASCII-дерево будут реализованы позже.

## Основные функции

### `src/cli.py`

- `build_parser()` создаёт описание аргументов командной строки.
- `add_load_order_option()` добавляет режим вывода порядка загрузки.
- `validate_repository()` проверяет адрес или путь к тестовому файлу.
- `validate_output()` проверяет имя и каталог выходного файла.
- `parse_args()` разбирает аргументы и проверяет обязательные параметры,
  глубину и расширение выходного файла.

### `src/repository.py`

- `load_index()` загружает и распаковывает `APKINDEX.tar.gz`.
- `parse_index()` преобразует записи индекса в словари полей пакетов.
- `find_package()` ищет пакет по точному имени и версии.
- `direct_dependencies()` получает содержимое поля прямых зависимостей.

### `src/graph.py`

- `dependency_name()` убирает ограничение версии из записи зависимости.
- `package_dependencies()` строит таблицу зависимостей всех пакетов.
- `resolve_dependency()` находит пакет, предоставляющий capability `so:...`.
- `parse_test_graph()` читает локальный граф в формате `A: B C`.
- `build_graph()` выполняет рекурсивный BFS с глубиной, фильтром и защитой
  от повторного посещения.
- `format_graph()` готовит связи графа для вывода в терминал.

### `src/load_order.py`

- `load_order()` выводит зависимости раньше нуждающихся в них пакетов.

### `src/main.py`

- `main()` объединяет разбор настроек, построение графа и вывод порядка.

## Запуск обычного режима

Команда для настоящего Alpine-репозитория:

```bat
run.bat --package curl --repository https://dl-cdn.alpinelinux.org/alpine/v3.24/main/x86_64/ --version 8.23.0-r0 --output result.svg --max-depth 2
```

Программа скачает `APKINDEX.tar.gz`, найдёт `curl` версии `8.23.0-r0` и
выведет связи до глубины 2.

Порядок загрузки для того же пакета:

```bat
run.bat --package curl --repository https://dl-cdn.alpinelinux.org/alpine/v3.24/main/x86_64/ --version 8.23.0-r0 --output result.svg --max-depth 2 --load-order
```

Версия в репозитории может измениться. Если указанная версия больше не
найдена, нужно указать доступную в репозитории версию пакета.

## Запуск тестового режима

Файл `test-data\graph.txt` содержит небольшой граф:

```text
A: B C
B: D
C: D
D:
```

Запуск:

```bat
run.bat --package A --repository test-data\graph.txt --test-mode --version 1.0 --output result.svg --max-depth 2
```

Порядок загрузки для тестового графа:

```bat
run.bat --package A --repository test-data\graph.txt --test-mode --version 1.0 --output result.svg --max-depth 2 --load-order
```

Ожидаемый порядок: `D`, `B`, `C`, `A`.

Проверка цикла:

```bat
run.bat --package LOOP_A --repository test-data\graph.txt --test-mode --version 1.0 --output result.svg --max-depth 5
```

Проверка порядка загрузки при цикле:

```bat
run.bat --package LOOP_A --repository test-data\graph.txt --test-mode --version 1.0 --output result.svg --max-depth 5 --load-order
```

Программа сообщит, что порядок определить нельзя.

Проверка фильтра:

```bat
run.bat --package A --repository test-data\graph.txt --test-mode --version 1.0 --output result.svg --max-depth 2 --filter B
```

Порядок загрузки с фильтром:

```bat
run.bat --package A --repository test-data\graph.txt --test-mode --version 1.0 --output result.svg --max-depth 2 --filter B --load-order
```

Проверка ограничения глубины до одного уровня:

```bat
run.bat --package A --repository test-data\graph.txt --test-mode --version 1.0 --output result.svg --max-depth 1 --load-order
```

## Запуск тестов

Из корневой папки проекта:

```bat
python -m pytest tests\test_cli.py -v
```

Или все тесты проекта:

```bat
python -m pytest -v
```

Тесты проверяют разбор параметров, обработку ошибок, разбор `APKINDEX`,
глубину BFS, фильтрацию, циклы и Alpine-зависимости с версиями и `so:`.

## Проверка четвёртого этапа

Добавьте `--load-order` к команде тестового графа выше. Для `A` порядок
будет `D, B, C, A`. Для проверки цикла добавьте `--load-order` к команде
с `LOOP_A`: программа сообщит,
что порядок загрузки определить нельзя.

Результат на реальном репозитории нужно сравнить с выводом `apk` для того же
пакета и записать найденные расхождения. `apk` учитывает версионные
ограничения, уже установленные пакеты и выбор поставщиков; текущая модель
строит порядок по разрешённому графу индекса.

### Пример сравнения с Alpine

Для `curl` версии `8.23.0-r0` из Alpine 3.24 наша программа с глубиной 2
вывела порядок:

```text
musl, ca-certificates-bundle, brotli-libs, c-ares, libcrypto3,
libidn2, nghttp2-libs, libpsl, libssl3, zstd-libs, zlib, libcurl, curl
```

В Alpine была выполнена отдельная симуляция, без установки пакетов:

```sh
apk update
apk add --simulate curl=8.23.0-r0
```

Вывод `apk` показал следующий план установки:

```text
brotli-libs, c-ares, libunistring, libidn2, nghttp2-libs,
libpsl, zstd-libs, libcurl, curl
```

В обоих результатах `libcurl` и `curl` идут после показанных зависимостей.
`libunistring` есть в плане `apk`, но отсутствует в нашем выводе с глубиной 2:
программа не исследует зависимости пакетов за этим пределом. Наша программа
выводит также, например, `musl` и `zlib`; симуляция `apk` показывает план
изменений для конкретной системы и может не перечислять уже установленные
пакеты. Для точного объяснения нужно проверить состояние этой системы.
План установки `apk` не следует считать измеренным порядком скачивания.
